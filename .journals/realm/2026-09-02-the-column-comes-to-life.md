# 2026-09-02 · The column comes to life

*A hand dealt by Caesura 🎻 (Fable, `claude-fable-5-1`), working only in `resonance-sistrum`; `resonance-awen` and every other repo read-only. No git writes, no base writes, no `.env`, no Android build. KP's word to start: **"go … fleet away my friend."***

**The ruling this serves, verbatim.** *"none of that belongs in the recorder, the recorder db structure simply requires a json column to handle the expected use case, the column will come to life when ready."* The column is `takes.provenance` — held open since 2026-08-12, a TEXT column of JSON that nothing validates and nothing may drop. The studio wrote the first key into it this morning (`{ studio: … }`). Tonight the rest arrived, and **`src-tauri/src/lib.rs` gained not one line of schema to let it** — only a longer comment saying what a document may now hold. That is the whole shape of the thing: the collaboration layer arrived *through* the held place, in the window, and the recorder was never touched to make room for it.

**The waters, crossed as mirrors.** `the-signet` · `the-clavis` · `the-lok` · `the-merismos`, copied byte-faithfully into `src/lib/{signet,clavis,lok,merismos}/index.ts`, each with its own `MIRROR.md` naming the source of truth in `resonance-awen` — the road `cosmic`, `cumdach`, `epagoge` and `sky` already travel in this body. SHA256 heads recorded at the copy: `C9EB0014B82A3C2D` · `2E3448EEB220FE20` · `78B75769881B9D33` · `C5354365B7718AC4`. Nothing in `resonance-awen` was edited or even opened for writing.

**What did NOT cross, and why it is the right answer.** Each of the clavis and the lok ships a reference host and a hand-written `host-surface.d.ts` that declares `crypto`, `CryptoKey` and `TextEncoder` at global scope — because those waters carry zero dependencies and pull in no lib. This body already has `lib.DOM`. Those declarations would collide with it, and the reference `generateKey` line does not typecheck against the DOM's own overloads. So the host is this app's, at `src/lib/keyring/hosts.ts`, line for line the same hand-off, typed against the DOM. That is not a departure — **it is what the water asks for.** `NO_KEY_STORAGE`, verbatim: *"Key storage is the HOST'S business… Where an entity's key lives and how it is protected is a question this tool does not answer and will not pretend to."*

**So this app answered it, out loud.** The keypair is generated ONCE through WebCrypto with the private half **non-extractable**, and held as `CryptoKey` objects in this device's own IndexedDB (`src/lib/keyring/store.ts`). Structured clone is the one road a non-extractable key can travel; it never becomes bytes to do it. There is no export path for the private half anywhere in the app, and the absence is the law. Two things follow, and both are said on the screen before the press rather than discovered later: the key **cannot be backed up or moved to another device**, and **the purge takes it** — the settings purge now deletes the keyring, because the house's ward is that the purge truly purges. Takes already sealed stay verifiable; nothing new can ever be sealed as that key again.

**Every seal signs.** Capture's save, the studio's mixdown, trim and overdub each read the take's own bytes over the road the mix already uses (`read_take_bytes`), claim them with the clavis, and write `{ studio?, signet, clavis }` into the column *beside* what was already there. **A seal is never blocked on a key**: no key seals with `signet` alone and says so; no signet seals with the studio's note alone and says so; a claim that throws is told, and the file was always safe first. Opening a take (`ProvenancePanel`, inside `TakePlayer`) verifies through the lok and prints its answer in the lok's own words — *open*, or *not open* and which of `malformed` · `digest mismatch` · `signature invalid`. Unreadable json is shown as the raw string, and every key this room does not read is listed by name.

**The splits, at the Mixdown.** One part per **distinct signet** found in the lanes' takes, keyed by public key rather than by name (two people may honestly share a name; none share a key), plus whoever is at the desk as `engineer` if they did not also play. `even()` by default — and the room says out loud that the remainder goes *whole to the first part the lanes listed*, which is the-merismos's own stated rule and not a rounding. Points editable, the sum shown, every fault named and nothing silently corrected. **Consent is a checkbox this device may tick on exactly one line** — the one whose identity holds its key. Every other line reads *awaiting consent*. There is no path in this room that consents on anyone's behalf, and `told` never rides into the column because telling is commentary, not a term.

**Gates, verbatim.** `npm run check` → `COMPLETED 372 FILES 0 ERRORS 0 WARNINGS`. `npm run build` → `✓ built in 11.68s`, `Wrote site to "build"`. `cargo check` in `src-tauri` → `Finished \`dev\` profile [unoptimized + debuginfo] target(s) in 2.90s`, exit 0. Proofs: `provenance-round-trip.mjs` 10/10 TRUE, `splits-from-lanes.mjs` 13/13 TRUE, and the three studio proofs re-run at exit 0. The store's own read and write path moved into `src/lib/provenance.ts` so the proofs walk **the road the app walks** rather than a copy of it.

**What did not hold, said plainly.** No key was made on a real device and no credential was verified against a real WAV — every proof here is over synthetic documents, and the crypto itself was exercised only by the type system. The Android `aarch64` check was not run and neither was any build. Nothing was heard. A merismos written into a mixdown cannot be edited afterwards from the TakePlayer — a split is redrawn at the next bounce, which is honest but is not yet a way for a collaborator to add their yes later on their own device. There is no revocation register and the lok says so at every answer. And the biggest one, named rather than implied: **consent here is one device's checkbox**, not four musicians each on their own machine; the shape is right and the road between devices does not exist yet.
